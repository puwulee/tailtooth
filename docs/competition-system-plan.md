# 戰鬥陀螺競賽系統 — 總體架構與規劃補強建議書

> 版本 v0.1 ｜ 文件用途：作為平台從 0 到 1 的總體規劃藍圖，並標示「目前規劃已涵蓋」與「缺漏需補強」之處，將競賽規則對齊國際/正規戰鬥陀螺賽（WBO 社群標準 + Beyblade X 官方賽制）。

---

## 0. 你目前規劃的盤點（已涵蓋）

你提出的需求其實已經是一個相當完整的「賽事營運平台」，整理如下：

| 面向 | 你已規劃的內容 |
|------|----------------|
| 報名 | 線上報名、兒童組／成人組、聯絡資訊、規範說明、贈品機制 |
| 金流 | LINE 作為唯一線上收款報名渠道、開立光貿電子發票 |
| 選手與裝備 | 選手管理、登錄自己的戰鬥陀螺、陀螺拍照去背加浮水印 |
| 賽程 | 對戰組合排序、活動表、賽程編排、複賽／冠軍戰場地抽選 |
| 場地 | 客戶端提交贊助場地、不同組別用不同場地、Google 位置＋環境照片 |
| 計分／成績 | 勝率計算、個人成績、杯賽成績、單顆陀螺績效、全站積分排名 |
| 角色 | 平台方／主辦單位／系統／裁判／參賽者 分級與不同操作介面 |
| 流程控管 | 裁判員記錄、賽事流程操控、戰鬥開始／結束記錄 |
| 公告／通知 | 電子檔案歸檔、社群平台、官方 LINE 投放、Email |
| 品牌 | 熱血沸騰但不過度暴力、適合少年與成人的風格 |

**這份規劃的強項**：你已經想到了「金流 → 報名 → 編排 → 賽務 → 成績 → 公告」的完整營運閉環，這是很多賽事平台會漏掉的。下面補強的重點集中在 **(A) 競賽規則的正規化**、**(B) 法遵與個資（尤其兒童）**、**(C) 系統技術可行性與離線賽務**。

## 1. 總體系統架構

### 1.1 技術選型建議（你寫的 "PHP + Pro + Ccode" 需要先確定）

建議明確定義技術棧，避免後期返工：

| 層 | 建議 | 說明 |
|----|------|------|
| 後端 | **PHP 8.2+ / Laravel 11** | 內建 RBAC、Queue、排程、Sanctum API、Eloquent ORM，賽事這類 CRUD + 流程系統開發最快 |
| 前端 | **Blade + Livewire** 或 **Vue 3 / Inertia** | 裁判即時計分介面建議走 SPA 體驗；公開頁可走 SSR 利於 SEO 與社群分享預覽 |
| 資料庫 | **MySQL 8 / MariaDB** | 主資料；賽程組合適合關聯式 |
| 快取／佇列 | **Redis** | 即時對戰看板、通知佇列、發票與 LINE 推播的非同步處理 |
| 檔案儲存 | **S3 相容物件儲存**（如 Cloudflare R2） | 陀螺照片、去背圖、賽事電子檔案 |
| 即時 | **Laravel Reverb / WebSocket** | 即時賽程看板、裁判計分同步 |
| 部署 | Docker + CI/CD | 賽事日流量尖峰，需可水平擴充 |

> 若團隊更熟悉純 PHP，可用 **Slim 4 + Eloquent** 輕量替代；但 Laravel 在「角色權限 + 排程通知 + 金流回呼」這三件事上節省最多工。

| 審核報名／退費 | ✅ | ✅ | ✅ | – | – |
| 賽程編排／場地抽選 | ✅ | ✅ | ✅ | – | – |
| 驗規（裝備檢查）登錄 | – | – | – | ✅ | – |
| 即時計分／判定 finish | – | – | – | ✅ | – |
| 申訴審理 | ✅ | ✅(主審) | – | ✅ | – |

### 1.4 外部整合清單（每一個都需要實作回呼與失敗重試）

| 整合 | 用途 | 補強重點 |
|------|------|----------|
| **LINE Pay** | 線上收款（你的唯一渠道） | 需處理付款回呼、付款逾時、重複付款、退款 API；要有「金流對帳」報表 |
| **LINE Login** | 報名身分綁定（建議） | 用 LINE Login 取得 userId，後續推播與身分一致，省去重複註冊 |
| **LINE Messaging API** | 官方帳號推播賽程/通知 | LINE Notify 已停用，務必走 Messaging API 的 push/multicast；注意每月免費推播額度 |
| **光貿電子發票 API** | 開立電子發票 | 需傳 buyer 統編/手機載具/捐贈碼；要處理「折讓單」（退費時）；發票字軌與作廢流程 |
| **Email（SendGrid/SES）** | 報名確認、賽程通知 | 退信處理、避免進垃圾桶（SPF/DKIM/DMARC） |
| **Google Maps / Places** | 場地位置 | 嵌入地圖、靜態圖、導航連結 |
| **社群平台（FB/IG）** | 公告投放 | 多數平台限制自動發文，務實做法是「一鍵產生圖文 + 手動發布」或走官方 Graph API（需審核） |

## 2. 核心資料模型（建議實體）

```
User（帳號）──< Role
Player（選手檔案：本名/暱稱/組別/監護人）──1:1── User
Beyblade（陀螺登錄：本體照片/去背圖/零件組合/規格）──< Player
Tournament（賽事：名稱/日期/組別設定/規則版本/獎品）
  └─< Division（組別：兒童組/成人組、賽制、計分規則）
        └─< Registration（報名：選手+票種+繳費狀態+發票)
Venue（場地：名稱/地址/座標/環境照片/是否贊助/容量)
Stage（賽段：分組賽/複賽/冠軍戰）──< Group（小組）
Match（對戰：A選手+陀螺 vs B選手+陀螺、場地、裁判、開始/結束時間)
  └─< Round（每一回合：finish 類型、勝方、得分)
ScoreRule（計分規則：finish→points 對照、勝負條件)
RankingPoint（積分紀錄：賽事→選手→積分)
Appeal（申訴：對戰、申訴方、理由、裁決)
AuditLog（不可竄改的賽務操作紀錄)
Sponsor（贊助方）──< Venue / Tournament
Notification（通知佇列：管道/狀態/重試)
ArchiveDoc（賽事電子檔案：PDF/圖卡/結果)
```

> 關鍵：**Match 必須同時記錄「選手」與「該場出戰的陀螺」**，這樣才能算出你要的「哪一顆陀螺績效最好」。

## 3. 賽務主流程

```
報名開放 → 線上報名(選組別/票種) → LINE Pay 付款 → 開立電子發票 → 報名確認(Email+LINE)
   → 報到當日：選手登錄/確認陀螺 → 裁判驗規(裝備合法性檢查) → 編排引擎產生賽程/場地分配
   → 分組循環賽(裁判即時計分) → 計算晉級 → 複賽(可抽選場地) → 冠軍戰(可抽選場地)
   → 結算名次/積分/單顆陀螺績效 → 產生電子檔案 → 公告投放(LINE/Email/社群)
```

每個節點都應有 **狀態機**（報名：待付款／已付款／已報到／棄賽；對戰：未開始／進行中／已結束／申訴中／已確認）。

## 4. 競賽規則設計（對齊國際/正規標準）★這是最需要補強的部分

你目前寫的「勝率乘積計算」在正規賽中其實**不是主要判定方式**。國際/官方戰鬥陀螺賽（WBO 社群標準與 Takara Tomy「Beyblade X」官方賽）都是 **點數制（Point-based finish）**。建議採用下列正規架構：

### 4.1 對戰勝負：採「Finish 點數制」（對齊 Beyblade X 官方）

| Finish 類型 | 說明 | 點數 |
|-------------|------|:---:|
| **Spin Finish（持續力勝）** | 對手陀螺先停止 | 1 |
| **Over Finish（場外勝/出場）** | 把對手陀螺打出戰鬥盤 | 2 |
| **Burst Finish（爆裂勝）** | 對手陀螺解體爆開 | 2 |
| **Xtreme Finish（極限勝）** | 將對手送入 Xtreme 專用區並出場（需 Xtreme Stadium） | 3 |

- **一場對戰（Match）**：採「先達 N 點獲勝」（官方常用 **先達 4 點**；可設定）。
- **賽制（Deck）**：官方常用 **3 顆陀螺一組（Deck Format）**，每回合可換不同陀螺；也可設定 **單顆（Solo）** 模式。
- 你要的「勝率」仍可保留為**統計指標**（顯示用），但**正式名次以點數/勝場為準**，避免勝率制被「少打場數」鑽漏洞。

### 4.2 賽制與賽程編排（編排引擎要支援）

| 賽制 | 用途 | 編排重點 |
|------|------|----------|
| **循環賽 Round Robin** | 分組賽，保證每人多場 | 人數多時分小組，組內全循環 |
| **瑞士制 Swiss** | 大量選手、場次有限 | 同分配對，避免重複對手 |
| **單敗淘汰 Single Elim.** | 複賽/決賽 | 需處理輪空(Bye)、種子排序(Seeding) |
| **雙敗淘汰 Double Elim.** | 較公平的淘汰 | 敗部復活，適合冠軍含金量高的賽事 |

編排引擎必備能力（**目前規劃缺漏**）：
- **種子排序（Seeding）**：依積分/過往成績排種，強者不早遇。
- **輪空（Bye）處理**：人數非 2 的次方時自動補輪空。
- **衝突偵測**：同一選手不可同時排兩場；同一場地不可同時兩場（場地時段表）。
- **場地抽選**：你要的「不同組別不同場地」「複賽/冠軍戰抽選場地」→ 設計成可記錄「抽選結果＋抽選人＋時間」以示公正。

### 4.3 裝備驗規（Beyblade Check）★目前完全缺漏，正規賽必備

正規賽在開賽前有「驗規／車檢」環節，建議補上：
- **合法零件**：限官方正版零件（依賽事指定世代，如 Beyblade X / Burst），禁止改造、磨改、非官方零件。
- **重量/規格檢查**：部分賽事限重；登錄時要求填寫零件組合（如 Beyblade X：Blade／Ratchet／Bit）。
- **發射器（Launcher）規範**：限官方發射器，禁止違規改裝。
- **驗規結果登錄**：裁判勾選通過/不通過，不通過需更換才能出戰；存證於 AuditLog。

### 4.4 計時、平手與判定

- **回合計時**：官方單回合上限（常見 **3 分鐘**），逾時依場上狀態判定（如雙方仍轉 → 視規則判 Spin 或重賽）。
- **平手（同時停止/同時出場）**：判定「無分（No Score）重打」或依規則。
- **判定爭議**：**申訴機制（目前缺漏）** — 限選手本人/隊長提出、限時（如該場結束 1 分鐘內）、由主審裁決、可調影像；裁決結果不可再申訴並存證。

### 4.5 個人成績 / 積分 / 單顆陀螺績效（把你的需求正規化）

- **賽事內名次**：分組賽積點 → 晉級 → 淘汰賽勝負 → 最終名次。
- **全站積分（賽季排行）**：建議用 **「賽事名次 → 積分」對照表**（如冠軍 100、亞軍 70…）累計賽季積分，比單純勝率更公允；進階可導入 **ELO/Glicko** 動態評分。
- **單顆陀螺績效**：以 Beyblade（陀螺）為維度統計 — 出戰場次、各 finish 次數、平均得分、勝率 → 產生「最佳陀螺組合（Meta）」榜，這對社群與銷售通路是很好的話題與內容。

## 5. 缺漏需補強清單（依優先級）

### 🔴 P0 — 不補會出事（法遵/公正/可營運）

1. **兒童個資與肖像權（最關鍵）**
   - 兒童組需 **監護人同意書**（報名流程內電子簽署）。
   - 陀螺/選手照片去背後要公告到社群 → 需 **肖像權／影像使用授權**，未成年需家長授權，並提供「撤回授權」管道（個資法、兒少權益）。
2. **電子發票折讓與退費政策**
   - 退費需開 **折讓單**；要定義退費規則（賽前 X 天全退、賽事取消全退等）並寫進報名條款。
3. **裝備驗規制度（見 4.3）** — 沒有驗規的比賽不具公信力。
4. **申訴與裁決機制（見 4.4）** — 爭議處理規則需事前公告。
5. **賽務操作存證（AuditLog）** — 計分、改分、抽選、裁決都要留痕，防作弊與事後爭議。
6. **賽事規則版本化** — 規則會逐屆調整，每場賽事綁定「規則版本」，避免成績爭議。

### 🟠 P1 — 影響賽事日體驗（強烈建議 MVP 就有）

7. **裁判離線計分（Offline-first）** — 賽事場地常網路不穩，計分介面要能離線暫存、回連後同步，否則賽事日會卡死。
8. **即時戰況看板** — 觀眾/選手即時看賽程與比分，提升現場熱度與品牌感。
9. **賽程衝突偵測 + 場地時段表** — 避免一人兩場、場地撞場。
10. **報名名額/票種控管** — 額滿、候補（waitlist）、組別人數下限不開組。
11. **報到（Check-in）流程** — QR Code 報到，未報到者自動棄賽不佔籤位。

### 🟡 P2 — 提升品牌與營運（可分期）

12. **影像處理 pipeline 明確化** — 去背可用 `rembg`/第三方 API；浮水印用 PHP GD/Imagick；產生統一「陀螺規格圖卡」更有質感。
13. **贊助方管理** — 贊助等級、Logo 露出位置、場地贊助審核流程、贊助成效報表（這直接連到你說的「銷售通路渠道提升」）。
14. **賽事電子檔案產生器** — 自動產生 PDF/圖文成績冊（含名次、最佳陀螺、精彩數據），一鍵投放各管道。
15. **多語系** — 若要「邀請各方好手」走向國際，預留 i18n（中/英/日）。
16. **排行榜與選手個人頁** — 選手戰績、徽章、賽季積分，做出「養成感」黏著度。
17. **防作弊/帳號審核** — 同一人重複報名、假帳號刷積分的偵測。

## 6. 法遵與個資（台灣情境）

- **個資法**：蒐集目的告知、同意取得、保存期限、選手可查詢/刪除。
- **兒少**：未成年報名一律監護人同意；肖像公告需另行授權。
- **金流/發票**：LINE Pay 對帳 + 光貿電子發票（含載具/捐贈/折讓）需與帳務報表勾稽。
- **賽事條款**：報名須勾選同意「競賽規則、退費政策、影像使用、個資告知」四份文件，並存版本與時間戳。
