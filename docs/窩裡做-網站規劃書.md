## 0. 文件導讀

本規劃書依據業主初步構想整理而成，並就原始構想中尚未明確之處主動補齊（補齊內容於各節以 **【補充建議】** 標示，供業主取捨）。文件涵蓋產品定位、會員與分潤、商品與內容、金物流、訂閱與 CRM、技術架構、後臺權限、資訊安全與法遵、資料模型、開發里程碑與風險控管。

「窩裡做」（在家裡做事之意）定位為**平臺式（Marketplace）手作服務電商**，核心精神是讓老師（賣家）能在自家完成手作教學與材料供應，並透過平臺販售實體商品、虛擬影音課程與長期訂閱服務。

## 1. 產品定位與商業模式

### 1.1 願景與定位
- **一句話定位**：專為「手作 / 手工藝 / 居家才藝」設計的多賣家電商與線上課程平臺。
- **平臺類型**：B2B2C Marketplace。平臺方（官方）提供基礎設施與信任機制，老師（賣家）自行上架經營，買家（客戶）跨賣家購買。
- **差異化重點**：
  1. 同時支援**實體商品 + 虛擬影音課程 + 材料包訂閱**三種商品型態。
  2. 針對每位賣家可**個別設定分潤費率**，營運彈性高。
  3. 內建以 **LINE 官方帳號**為核心的客戶維護與再行銷機制。

### 1.2 角色定義
| 角色 | 說明 | 主要行為 |
|------|------|----------|
| 訪客（Guest） | 未登入者 | 瀏覽商品、查看課程介紹、註冊 |
| 買家 / 客戶（Customer） | 一般消費者 | 下單、付款、觀看已購影片、訂閱、評價、查詢訂單 |
| 老師 / 賣家（Seller） | 上架商品的創作者 | 上架／管理商品、設定庫存與影片、查看訂單與撥款、回覆客戶 |
| 官方賣家（Official） | 平臺方以賣家身分上架 | 與賣家相同，但抽成費率由平臺自訂（通常較低） |
| 平臺管理員（Admin） | 平臺營運方 | 審核商品、管理賣家、設定分潤、類別 CRUD、查閱所有訂單、金物流總覽、系統設定 |

> **【補充建議】** 建議在 Admin 之下再細分**權限角色（RBAC）**：超級管理員、商品審核員、財務（撥款／對帳）、客服。避免單一超級帳號權限過大，符合商用等級的最小權限原則。

### 1.3 收益來源
1. **系統服務費（分潤抽成）**：依賣家與商品性質個別設定費率（主要收入）。
2. **官方自營商品毛利**：官方上架商品的銷售收益。
3. **訂閱服務分潤**：材料包／影音訂閱的週期性抽成。
4. **【補充建議】加值服務費（選配）**：金流手續費轉嫁、置頂／廣告曝光、進階賣家方案月費等。

## 2. 會員系統與分潤機制

### 2.1 註冊與身分
- 註冊方式：Email + 密碼；**【補充建議】** 同時支援 **LINE Login**、Google 第三方登入（與後續 LINE CRM 串接相輔相成）。
- 註冊後可選擇身分：**買家**、**老師（賣家）**。管理員身分不開放自助註冊，由既有管理員指派。
- **賣家審核流程**：申請成為賣家 → 填寫個人／商號資料、收款帳戶、實名與發票資訊 → 管理員審核 → 通過後方可上架。
- 一個帳號可同時具備「買家」與「賣家」身分（賣家也能購買他人商品）。

### 2.2 分潤（系統服務費）機制
- **費率設定維度**：可依「賣家」「商品類別」「單一商品」三層級設定，採就近覆蓋（商品 > 類別 > 賣家預設）原則。
- **官方商品**：抽成比例由平臺方自訂，通常較低或為 0。
- **撥款規則（【補充建議】）**：
  - 設定撥款週期（如月結、半月結）與最低撥款門檻。
  - 鑑賞期 / 退貨保留期內的款項先行凍結，期滿再計入可撥款餘額。
  - 平臺保留金流手續費、退款／退費的拆帳處理規則。
- **分潤試算公式（範例）**：
  ```
  賣家實得 = 商品售價 − 平臺服務費（售價 × 費率）− 金流手續費分攤 − 退款調整
  ```
- 系統需保留每筆交易的**分潤明細快照**（成交當下的費率），避免事後調整費率影響歷史帳務。

### 2.3 帳務透明度
- 賣家後臺提供：銷售報表、分潤明細、撥款紀錄、對帳單下載（CSV／PDF）。
- 管理員後臺提供：全平臺金流總覽、各賣家應撥金額、手續費彙總。

## 3. 商品管理與類別

### 3.1 類別（Category）
- **預設手作服務相關類別（10–15 個建議清單）**：
  1. 烘焙甜點
  2. 手沖咖啡 / 茶飲
  3. 編織 / 鉤針
  4. 刺繡 / 布作
  5. 黏土 / 陶藝
  6. 手工皂 / 香氛蠟燭
  7. 飾品 / 金工
  8. 繪畫 / 插畫
  9. 紙藝 / 卡片
  10. 木工 / 皮革
  11. 花藝 / 乾燥花
  12. 親子手作
  13. 居家修繕 DIY
  14. 烹飪料理
  15. 其他手作
- 類別由管理員進行 **CRUD**；支援**階層（父子分類）**、排序、啟用／停用、SEO 友善的 slug。
- 商品可掛載多個類別（多對多）；**【補充建議】** 增加「標籤（Tag）」做更彈性的搜尋與篩選。

### 3.2 實體商品（Physical Product）
- 完整賣場欄位：標題、副標、描述（富文本）、價格、特價、**庫存管理（SKU / 規格組合）**、商品照片（多張）、商品影片、運費設定、上架／下架排程。
- **規格（Variant）**：如顏色、尺寸、材料包選項；各規格獨立庫存與價格。
- 庫存策略：下單即時扣庫存 / 付款後扣庫存（可設定）；低庫存警示。

### 3.3 虛擬商品 — 影音內容（Digital / Video Product）
- 影片來源兩種：
  1. **自家伺服器上傳**（建議搭配物件儲存 + 串流轉檔，見 §6.3）。
  2. **外部嵌入**：YouTube（含非公開連結）、Vimeo 等。
- 觀看權限規則：
  - 客戶**購買後**方可於「我的課程 / 訂單」中重複播放。
  - 每支影片可**自訂播放期限**（如購買後 30 天、180 天或永久）。
  - **【補充建議】防盜錄與保護**：自家影片採**簽章串流網址（Signed URL，短時效）**、禁止直接下載、動態浮水印（顯示購買者帳號／訂單編號），降低盜版風險。
- 觀看紀錄：記錄觀看進度、到期提醒。

### 3.4 商品審核
- 賣家送出上架 → 狀態為「待審核」→ 管理員審核（通過／退回並附原因）→ 上架。
- 官方商品可設定免審或自動通過。
- 審核紀錄與版本留存，便於稽核。

## 4. 金流與物流

### 4.1 金流
- **支付方式**：**綠界 ECPay** 與 **LINE Pay**。
- 串接要點：
  - 綠界：信用卡、ATM 虛擬帳號、超商代碼等（依需求開通）；採用其幕後通知（ServerPost / Webhook）確認付款結果，**不可僅信任前端導回**。
  - LINE Pay：Request / Confirm 兩段式流程，需妥善處理 confirm 逾時與重試。
- **多賣家金流的關鍵議題（【補充建議】）**：
  - 一張購物車可能含多個賣家商品。需決定**金流模式**：
    - (A) **平臺代收代付**：款項先進平臺，再依分潤撥款給賣家（多賣家最常見、最易控管）。
    - (B) 分拆付款（較複雜，金流商支援度有限）。
  - 建議採 **(A) 平臺代收代付**，並落實金流與分潤帳務分離。
- 交易狀態機：`待付款 → 已付款 → 處理中 → 已出貨／已開通 → 已完成 → (退款／取消)`。
- 對帳：每日與金流商對帳檔比對，異常告警。

### 4.2 物流
- 物流範圍涵蓋**規劃、記錄與追蹤**；**物流資訊由用戶端（賣家／買家）自行輸入**。
- 支援配送方式：宅配、超商取貨、面交／自取（手作課程可能含實體材料包）。
- 物流欄位：收件人、地址、聯絡方式、物流單號、配送狀態、預計到貨。
- 虛擬商品免物流，付款完成即自動開通觀看權限。
- **【補充建議】** 物流狀態變更同步通知買家（Email / LINE）；保留是否未來串接物流 API（如超商物流）的擴充空間。

## 5. 訂閱制與客戶關係管理（CRM）

### 5.1 訂閱服務
- 標的：**影音課程訂閱**與**材料包定期配送**。
- 訂閱方案：月繳 / 季繳 / 年繳；可設定方案內容、價格、續訂規則。
- 計費：搭配金流商的定期定額（綠界定期定額 / LINE Pay 自動扣款）或平臺自建排程扣款。
- 生命週期：`訂閱中 → 即將到期 → 已續訂 / 已取消 / 已逾期`，並處理扣款失敗的重試與寬限期。

### 5.2 定期提醒與再行銷
- **按月**透過 **Email** 或 **LINE 官方帳號**發送通知：續訂提醒、新課上架、材料包出貨、關懷訊息。
- 排程：以 Laravel Scheduler + Queue 實作（見 §6），確保大量發送不阻塞。
- **【補充建議】** 提供分眾條件（依購買類別、消費金額、活躍度）做精準推播，並記錄發送與點擊成效。

### 5.3 LINE 整合
- 後臺需提供 **LINE 官方帳號**與 **LINE Messaging API** 的設定介面：Channel ID / Secret / Access Token、Webhook URL、訊息範本管理。
- 功能：綁定會員（LINE Login 取得 userId）、推播訊息、自動回覆、圖文選單導購。
- 注意 LINE Messaging API 的**推播訊息額度與計費**，超量改用分眾或 Email 備援。

## 6. 技術規格與系統架構

### 6.1 技術選型
| 項目 | 選用 | 說明 |
|------|------|------|
| 語言 | **PHP 8.2+** | 全平臺統一 |
| 框架 | **Laravel 11（最新 LTS 取向）** | 商用等級、生態完整 |
| 資料庫 | **PostgreSQL 15+** | 主資料庫 |
| 快取 / 佇列 | **Redis** | 快取、Session、Queue、限流 |
| 全文搜尋（選配） | Laravel Scout + Meilisearch | 商品搜尋 |
| 物件儲存 | S3 相容（自架 MinIO 或雲端） | 影片、圖片 |
| 前端 | Blade + Livewire / Inertia + Vue（擇一） | 後臺與商城 |
| 即時轉檔 / 串流 | FFmpeg + HLS | 自家影片串流 |

> **【補充建議】框架可省時並具基礎資安的建議套件**：
> - **Laravel Breeze / Jetstream**：認證骨架（登入、註冊、雙因素）。
> - **Spatie laravel-permission**：RBAC 角色權限。
> - **Laravel Cashier / 自建訂閱**：訂閱計費。
> - **Spatie laravel-medialibrary**：圖片／影片附件管理。
> - **Laravel Telescope（開發）/ Horizon**：偵錯與佇列監控。
> - **Spatie laravel-backup**：資料庫與檔案備份。
> - **Laravel Sanctum**：API Token（行動端或前後分離時）。
> - 綠界、LINE Pay 可用社群套件或官方 SDK 包裝。

### 6.2 系統架構（邏輯分層）
```
┌────────────────────────────────────────────┐
│  使用者端：商城前臺 / 賣家後臺 / 平臺後臺      │
└───────────────┬────────────────────────────┘
                │ HTTPS
┌───────────────▼────────────────────────────┐
│  Laravel 應用層                              │
│  ├─ 認證授權（RBAC）                         │
│  ├─ 商品 / 訂單 / 金流 / 分潤 / 訂閱模組      │
│  ├─ Webhook 接收（綠界 / LINE Pay / LINE）   │
│  └─ Queue Worker（通知、轉檔、撥款計算）      │
└──────┬───────────────┬──────────────┬───────┘
       │               │              │
  ┌────▼───┐      ┌────▼────┐    ┌────▼─────┐
  │Postgres│      │  Redis  │    │ 物件儲存  │
  └────────┘      └─────────┘    └──────────┘
       外部服務：綠界 / LINE Pay / LINE Messaging API / SMTP
```

### 6.3 影音處理流程
1. 賣家上傳原始影片 → 暫存物件儲存。
2. Queue 觸發 FFmpeg 轉 HLS 多解析度 + 產生縮圖。
3. 完成後標記可用；播放時以**短效簽章網址**授權，避免外流。
4. 外部嵌入（YouTube/Vimeo）則僅儲存連結與權限對應。

### 6.4 非功能性需求（NFR）
- **效能**：商品列表頁回應 < 500ms（快取輔助）；支援水平擴充。
- **可用性**：目標 99.9%；無狀態應用層 + 健康檢查。
- **可維護性**：模組化、測試覆蓋、CI/CD。
- **可觀測性**：集中式日誌、錯誤追蹤（如 Sentry）、佇列與金流告警。

## 9. 資訊安全與法令遵循

### 9.1 資安（商用等級）
- 全站 **HTTPS**、HSTS；密碼以 bcrypt/argon2 雜湊。
- Laravel 內建 **CSRF、XSS 轉義、SQL 注入（Eloquent 參數化）** 防護，搭配輸入驗證。
- **敏感金鑰**（金流、LINE Token）存於環境變數 / 加密設定，不入版控。
- **Webhook 驗簽**：綠界 CheckMacValue、LINE 簽章驗證，防偽造通知。
- 後臺登入建議 **2FA**、登入紀錄與 IP 限制；管理操作留稽核軌跡（Audit Log）。
- 上傳檔案掃描與型別／大小限制；API 限流（Rate Limiting）。
- 定期備份（Spatie backup）與還原演練。

### 9.2 法遵（臺灣）
- **個人資料保護法**：蒐集告知、隱私權政策、會員資料刪除權。
- **電子發票**：串接財政部電子發票（綠界可代開），符合開立規範。
- **消費者保護**：七天鑑賞期規範（數位影音商品依例外條款於購買頁明確告知不適用鑑賞期）。
- **服務條款 / 賣家合約 / 退換貨政策**頁面齊備。

## 11. 風險與對策

| 風險 | 影響 | 對策 |
|------|------|------|
| 多賣家金流拆帳複雜 | 帳務錯誤、撥款爭議 | 採平臺代收代付、費率快照、每日對帳 |

| LINE 推播額度 / 計費 | 成本上升 | 分眾推播、Email 備援、成效追蹤 |
| 金流／物流外部依賴 | 服務中斷 | Webhook 重試、狀態機補償、告警 |
| 個資外洩 | 法律與商譽 | 加密、最小權限、稽核、備份 |

## 12. 待業主確認事項（Open Questions）

1. 多賣家金流是否確認採「平臺代收代付」模式？
